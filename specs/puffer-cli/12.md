# Desktop Provider Alias Canonicalization

The desktop daemon protocol accepts user-facing provider aliases at its JSON
RPC boundary and normalizes them before provider registry lookup.

Canonical mappings:

- `codex` -> `openai`
- `claude` -> `anthropic`

Affected desktop RPC paths:

- `run_agent_turn` turn options
- `create_session` routing options
- `list_provider_models`

Model ids with matching aliased provider prefixes, such as `codex/gpt-5`, are
normalized against the canonical provider before the model is resolved. Unknown
provider ids remain unchanged so custom providers continue to fail with the
original id in diagnostics.
