# Browser Command Failure Session Guard

Browser command failures are scoped to the backend browser session that issued
the command.

Contract:

- Reload, history, resize, input, paste, wheel, and copy-selection failures
  capture the active backend browser session before dispatch.
- A delayed command failure updates the visible error banner only when that
  same backend session is still active.
- Switching browser tabs or agents before a command failure resolves must not
  pollute the new active tab.
- Copy-selection success/status updates are ignored if the user changes the
  active backend browser session before the command resolves.

Regression coverage lives in
`apps/puffer-desktop/tests/desktop-ui.spec.ts`.
