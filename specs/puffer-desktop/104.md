# Pipelines Draft Interaction Stability

Switching a workflow trigger between subscription and cron modes must not erase
the fields the user already typed for either mode. Local starter workflows must
also remain editable while daemon workflow loading is pending or failing.

Contract:

- Each workflow tracks in-memory trigger drafts per trigger type.
- Switching from subscription to cron remembers source topic and pattern.
- Switching from cron to subscription remembers the cron expression.
- Switching back restores the previous values for that trigger type.
- New workflows still use the existing default subscription and cron values.
- Trigger type selection uses explicit buttons rather than a select so the
  transition maps directly to one state mutation.
- Starter draft hydration reads existing local storage before persistence is
  enabled, preventing remounts from overwriting a saved draft with defaults.
- Local edits write a draft snapshot synchronously from the mutator so immediate
  tab switches do not race the persistence effect.
- Empty or failed workflow-list refreshes prefer the current local draft over
  the refresh-start snapshot so in-flight user edits survive late responses.
- Workspace-root defaulting only rewrites editor workflows when a value actually
  changes, avoiding a self-triggering Svelte effect loop.

Regression coverage lives in
`apps/puffer-desktop/tests/pipelines-ui.spec.ts`.
