# Composer Provider Model Guard

## Summary

The chat composer now validates the selected model against the selected
provider's loaded model list before a turn can be sent.

## Behavior

- Session/provider routing still initializes from the session record first.
- Provider aliases such as `codex` continue to resolve to the daemon's OpenAI
  provider for model discovery and turn requests.
- Once models for the selected provider are loaded, a model that is not in that
  provider's list is replaced with the provider default, or the first listed
  model.
- Thinking controls are reset when this fallback changes the selected model.

## Compatibility

Existing valid provider/model pairs are unchanged. Invalid persisted or default
cross-provider pairs such as OpenAI with a Claude model are corrected before the
composer sends a turn request.
