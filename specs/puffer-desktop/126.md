# Canonical Provider IDs For Model Listing

The desktop model picker resolves user-facing provider aliases before requesting
models from the daemon.

`listProviderModels` canonicalizes provider ids through the shared provider-id
mapping before issuing `list_provider_models`. This keeps Codex and Claude
sessions compatible with daemon provider ids even when settings snapshots expose
alias ids such as `codex` or `claude`.

The caller still keeps its UI provider id and label, so Codex remains displayed
as Codex while the daemon receives `openai`. This matches session creation and
turn submission behavior.

Regression coverage lives in `apps/puffer-desktop/tests/chat-session-ui.spec.ts`
and verifies that a Codex provider summary loads models from the OpenAI daemon
provider instead of showing an empty Codex model list.
