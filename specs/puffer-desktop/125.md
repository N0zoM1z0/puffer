# Files Inactive Save Failure State

The Files pane preserves save failures for the file that produced them, even
when the user switches to another tab before the daemon response arrives.

Save error state is keyed by absolute file path. Activating a tab restores that
file's pending save error into the viewer header, while unrelated tabs remain
unaffected. Closing a tab removes its cached save error. Starting a new save,
canceling edits, or receiving a successful save clears the error for that same
path.

`saveEditing` captures the target path before issuing `write_file` and records
the failure on that target path regardless of the active tab at completion time.
This keeps failed inactive saves visible when the user returns to the file, with
the dirty marker and Save action still available for retry.

Regression coverage lives in `apps/puffer-desktop/tests/files-workspace-ui.spec.ts`
and delays a failing `write_file`, switches away before the failure resolves,
then returns to the original file and asserts that the failure text, dirty
marker, and Save button are still visible.
