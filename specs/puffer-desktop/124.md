# Canonical Provider IDs For Chat Turns

The desktop chat path treats `codex` and `claude` as user-facing aliases and
sends daemon canonical provider ids to runtime RPCs.

`ConversationView` still displays Codex and Claude labels, accepts legacy
session metadata, and matches authenticated providers through alias-aware
comparison. When it resolves a provider for model loading or turn submission, it
canonicalizes the selected provider id before handing it to the daemon. This
prevents a provider summary entry with id `codex` from leaking into
`run_agent_turn`.

The desktop API adapter also canonicalizes `providerId` for `create_session` and
`run_agent_turn` before sending requests. This keeps non-composer callers and
the Tauri fallback path aligned with the daemon provider registry, where OpenAI
and Anthropic are canonical ids.

Regression coverage lives in `apps/puffer-desktop/tests/chat-session-ui.spec.ts`
and asserts that Codex-facing sessions send `providerId: "openai"` while keeping
model, thinking, fast mode, and permission options intact.
