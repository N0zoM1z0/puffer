# Files Inactive Save Completion

The Files pane applies successful save responses to the saved file even when the
user has already switched to another file tab.

`saveEditing` captures the target path and submitted content before issuing
`write_file`. When the daemon returns, the target file cache and draft cache are
updated for that target unconditionally. If the current draft for the target is
unchanged from the submitted content, the draft is reset to the persisted file
content and the dirty marker clears. If the user has since typed a newer draft
for the same target, that newer draft remains dirty.

Only active-view side effects remain gated by `activePath === target`: LSP popup
state is cleared only when the saved file is still visible. This avoids clearing
symbol context for another active file while still keeping inactive file tabs in
sync with successful daemon saves.

Regression coverage lives in `apps/puffer-desktop/tests/files-workspace-ui.spec.ts`
and delays `write_file`, switches to another tab before completion, then returns
to the saved file and asserts that the dirty marker and Save button are gone.
