# Files Save Draft Preservation

The Files editor must not discard text typed after a save request has been
sent but before its daemon response returns.

Contract:

- Saving captures the submitted editor content before awaiting `write_file`.
- When the response returns, the saved file result resets the draft only if the
  current draft still matches the submitted content.
- If the user typed a newer draft for the same path during the pending save,
  the new draft remains visible and the tab stays dirty against the saved
  baseline.
- Existing save failure and cross-tab save behavior remain unchanged.

Regression coverage lives in
`apps/puffer-desktop/tests/files-workspace-ui.spec.ts`.
