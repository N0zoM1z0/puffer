# Browser New Tab Response Ordering

The Browser pane preserves the newest active tab selection when multiple
new-tab requests resolve out of order.

Contract:

- Each new-tab click receives a monotonically increasing open-request serial.
- A late response for an older new-tab request may add its tab to the local tab
  list, but it must not replace the active tab selected by a newer request.
- Newer successful opens still activate the created tab and connect it to the
  daemon browser session.
- Tab-list clears or session switches remain stronger invalidation barriers and
  still prevent late open responses from resurrecting stale tabs.

Regression coverage lives in
`apps/puffer-desktop/tests/desktop-ui.spec.ts`.
