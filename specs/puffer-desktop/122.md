# MCP Server Management

Settings -> MCP Servers supports a full management loop for user and workspace
MCP manifests exposed by the daemon.

The desktop daemon exposes `update_mcp_server`, `remove_mcp_server`, and
`test_mcp_server` alongside the existing list/add RPCs. Update and remove are
limited to editable workspace or user resource files under
`.puffer/resources/mcp_servers` or `$PUFFER_HOME/resources/mcp_servers`; builtin
servers remain read-only. Update validates the requested id and transport, writes
the replacement YAML manifest, and removes the prior manifest when the id is
renamed. Remove deletes the selected manifest file and reloads resources before
returning the refreshed server list. Test validates that the selected server is
still discoverable and has the required target or endpoint for its transport.

The Settings screen renders Test, Edit, and Remove actions for every server card.
Builtin cards keep Edit and Remove disabled. Editing a managed server hydrates
the add form as an edit form and submits through `update_mcp_server`; removing a
server submits through `remove_mcp_server`; testing a server submits through
`test_mcp_server`. All operations keep the list synchronized with the daemon
response and surface the daemon result in the existing settings note area.

Regression coverage lives in `apps/puffer-desktop/tests/settings-ui.spec.ts` and
asserts that builtin servers are read-only, a managed server can be tested,
edited, and removed, and the expected daemon RPC payloads are sent.
