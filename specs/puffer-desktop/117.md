# Legacy Provider Alias Resolution

- Area: Corbina desktop chat composer and model controls
- Change: legacy session provider aliases resolve against the current settings provider list before model discovery and turn submission.
- Compatibility: sessions already using canonical provider ids are unchanged; aliases still display as user-facing Codex/Claude labels.

## Design

Some sessions can carry historical or local provider ids such as `codex`, while the connected daemon exposes canonical provider ids such as `openai`. The chat composer now resolves the selected provider through `settingsSnapshot.providers` using the existing provider-id equivalence rules before calling `list_provider_models` or `run_agent_turn`.

This keeps old sessions usable after connecting to a daemon whose provider registry only contains canonical ids.

## Regression

`chat-session-ui.spec.ts` opens a legacy `codex` session while settings only expose `openai`, verifies the model picker can show the OpenAI model, and asserts the turn request sends `providerId: "openai"`.
